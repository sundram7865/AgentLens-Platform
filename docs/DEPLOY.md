# Deploying free

Render (API + embedded workers) · Neon (Postgres) · Upstash (Redis) · Vercel
(dashboard). Every tier here is permanently free and none requires a card.

The two free-tier constraints that actually shape the configuration are the
worker-service gap on Render and the command budget on Upstash. Both are handled
below rather than discovered in production.

---

## 1. Neon: Postgres

Create a project. From the connection details, take **both** strings:

```
# POOLED: host contains "-pooler". API and workers.
postgresql://user:pw@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require

# DIRECT: same host WITHOUT "-pooler". Alembic only.
postgresql://user:pw@ep-xxx.region.aws.neon.tech/neondb?sslmode=require
```

**Using the wrong one in the wrong place is the single most common way this
deployment breaks**, so the platform handles the parts it can:

* `sslmode` and `channel_binding` are stripped from the async URL: asyncpg does
  not understand either and raises on connect, and TLS is re-expressed as a
  connect arg.
* On a pooled host, asyncpg's prepared-statement cache is disabled. PgBouncer in
  transaction mode can hand the next statement a different backend connection,
  where the cached plan does not exist.
* Alembic uses `OBS_DATABASE_DIRECT_URL`. If it is unset, migrations fall back to
  the pooled string and log a loud warning: PgBouncer can strand the advisory
  lock Alembic takes and hang the deploy.

**Free tier:** 0.5 GB storage, compute scales to zero when idle, 6-hour PITR.
The retention job keeps storage bounded; see [`RUNBOOK.md`](RUNBOOK.md) for
backups beyond the 6-hour window.

## 2. Upstash: Redis

Create a database, take the **TLS** URL: `rediss://default:<password>@<name>.upstash.io:6379`.

### The command budget, arithmetic included

The free tier allows **10,000 commands/day**. A naive consumer polling every
100 ms burns 864,000 commands a day doing nothing at all.

This platform blocks instead of polling. With `OBS_CONSUMER_BLOCK_MS=30000`
(the value `render.yaml` sets):

```
3 consumer groups × (86,400s / 30s)   = 8,640 XREADGROUP/day at idle
```

That is already most of the budget, so `render.yaml` also relies on Render's free
tier sleeping after 15 minutes idle; a sleeping API issues no commands at all.
In practice a demo deployment uses a few hundred commands a day.

Under real traffic each command carries up to `OBS_CONSUMER_BATCH_SIZE` (200)
messages, so throughput costs far fewer commands than events.

**If you exceed the budget**, raise `OBS_CONSUMER_BLOCK_MS`, reduce
`OBS_WORKER_ROLES` to `storage,guardrail`, or move Redis to a container on
Render (paid) or Fly.io.

## 3. Render: API and workers

```bash
# Blueprint: point Render at the repo; render.yaml does the rest.
```

Then set in the dashboard (never in git):

| Variable | Value |
|---|---|
| `OBS_DATABASE_URL` | Neon **pooled** |
| `OBS_DATABASE_DIRECT_URL` | Neon **direct** |
| `OBS_REDIS_URL` | Upstash `rediss://` |
| `OBS_BOOTSTRAP_ADMIN_EMAIL` | your login |
| `OBS_BOOTSTRAP_ADMIN_PASSWORD` | a real password, not the example |
| `OBS_CORS_ORIGINS` | your Vercel URL |

`OBS_JWT_SECRET` is generated by Render (`generateValue: true`). The app
**refuses to boot** in production with the example secret or one under 32
characters; failing a deploy beats running with a signing key that is in git.

### Why one service, not two

Render's free tier has **no background-worker service type**. Rather than
quietly requiring a paid plan for a deployment the README calls free, the
consumers run inside the API process:

```yaml
OBS_EMBED_WORKERS_IN_API: "true"
OBS_WORKER_ROLES: storage,guardrail,eval,scheduler
```

Same supervisor, same consumers, same graceful shutdown; only the process
boundary differs. On a paid plan set it to `false` and uncomment the worker
service in `render.yaml`. No code changes.

### Cold starts

The free tier stops the service after 15 minutes idle; the next request takes
~50 seconds to wake it. The dashboard treats this as a first-class state: the
API client retries once with a long timeout and the UI says "waking the API up"
rather than showing an error.

Consequence worth stating plainly: **while asleep, nothing is consumed.** Events
accumulate in Redis (bounded by `MAXLEN ~ 50000`) and are processed on wake.
Scheduled jobs use `job_runs` to detect they are overdue and run immediately on
wake, rather than silently skipping the window they slept through. This is also
why `pg_cron` is not used: a suspended Neon compute skips its jobs with no
indication that it did.

## 4. Vercel: dashboard

Root directory `apps/dashboard`. One environment variable:

```
OBS_API_URL = https://obs-platform-api.onrender.com
```

Note it is **not** prefixed `NEXT_PUBLIC_`. Only server components read it; the
browser never calls the API directly, which is what keeps the session token in
an httpOnly cookie that client JavaScript cannot read.

## 5. Point your agent at it

In SupportPilot's environment:

```env
OBS_ENABLED=true
OBS_REDIS_URL=<the same Upstash URL>
OBS_SERVICE=supportpilot
OBS_ENVIRONMENT=production
```

Full instructions: [`integrations/supportpilot/README.md`](../integrations/supportpilot/README.md).

## 6. Smoke-test the deployment, not localhost

```bash
API=https://obs-platform-api.onrender.com

curl -s $API/health | jq                      # may take ~50s on a cold start
curl -s $API/health/meta | jq '.status, .problems'

TOKEN=$(curl -s -X POST $API/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"...","password":"..."}' | jq -r .access_token)

# Submit a real ticket in SupportPilot, then:
curl -s "$API/v1/traces?limit=1" -H "Authorization: Bearer $TOKEN" | jq '.items[0].trace_id'

# PII redaction, as a viewer:
curl -s "$API/v1/traces/<id>" -H "Authorization: Bearer $VIEWER_TOKEN" | jq .input

# Injection flagging:
curl -s "$API/v1/traces?flagged=true" -H "Authorization: Bearer $TOKEN" | jq '.items[0].guardrail_flags'
```

## 7. Pre-flight checklist

- [ ] `OBS_JWT_SECRET` generated, not the example value
- [ ] `OBS_BOOTSTRAP_ADMIN_PASSWORD` changed, and changed again after first login
- [ ] `OBS_DATABASE_DIRECT_URL` set to the **non**-pooler host
- [ ] `OBS_CORS_ORIGINS` is your Vercel origin, not `*`
- [ ] `OBS_DOCS_ENABLED=false`: do not publish the OpenAPI schema of a data API
- [ ] `OBS_RETENTION_DAYS` set; Neon free is 0.5 GB
- [ ] `OBS_EVAL_PROVIDER` deliberately `none`, or a budget cap you are happy with
- [ ] `/health/meta` returns `"status": "ok"` after traffic
- [ ] A backup has been taken **and restored once** ([`RUNBOOK.md`](RUNBOOK.md))
